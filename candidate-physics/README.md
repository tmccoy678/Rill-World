# Inactive candidate physics

Status: source-only design. Nothing in this directory is built, deployed, or
connected to the continuing runtime.

The purpose is to reduce the next possible local system to physical primitives
without assigning a target form, task, interpretation, or human-authored
message. The current runtime remains authoritative until a separately reviewed
candidate is deliberately promoted at a lineage boundary.

See:

- `PRIMITIVES.md` for the allowed local vocabulary and invariants.
- `COMPARATIVE-REQUIREMENTS.md` for transport, gating, growth, damage, and
  distributed-integration requirements extracted without biological labels.
- `HARDWARE-STRUCTURE-REQUIREMENTS.md` for nested scale, boundary-controlled
  transfer, repeated arrays, shared exchange, and distributed regulation
  derived from direct visual study of Agar's hardware family.
- `AGAR-CONSTRAINTS.md` for the measured Intel memory hierarchy and candidate
  resource envelope.
- `SINGLE-FILE-CARRIER.md` for the first bounded mechanical trial.
- `experiment-01/` for the approved inactive one-carrier apparatus and local
  equations; it remains separate from the continuing runtime.
- `OPEN-QUESTIONS.md` for choices that remain unresolved and must not be hidden
  inside an implementation.

An executable must not be added until every implemented rule can be traced to a
stated primitive and each unresolved choice it settles is documented.
